# Authorized player-experience study

Purpose: produce combat-design learnings, not optimize a cheat/player-win product. Game4056467 remains frozen, no balance/camera/deployment changes. One normal default. Research modes explicitly labelled.

1. Blind visual recognition: at least six fresh pre-contact sequences, no debug/event text or answer key shown to visual reviewer. Commit predictions before reveal. Log direction/type/likely answer/confidence and uncertainty; count failures, do not turn a handful of samples into a human accuracy rate.
2. Sound: fresh native real-time audio/video capture with actual WebAudio output, tick/time receipts and no audible Mac speaker output. Audit existing enemy-charge cue and explain what sound can/cannot tell the player. Fake page-clock recordings do not establish AV sync.
3. Touch: actual trusted touch events for draw, slash, stab, heavy hold, directional guard, parry tap, short-step/roll, feint, release/cancel. Action-start/contact proof separate from presses. Level-matched special if reachable; report exclusions. No physical-thumb/latency guarantee.
4. Profiles: Goblin/Veteran/Executioner, beginner/intermediate/advanced, three matched seeds each in engine (27), one representative matched seed each in real rendered browser (9). L6 longsword/no-equipped-specials, no workarounds, all outcomes retained. Win competence separate from research value. Profiles are synthetic, not measured player populations.
5. Findings: each has reproducible setting/clip, observed problem or strength, player consequence, smallest proposal, confidence and retest. Separate bot/measurement defects from game changes. Complete required checks and independent review; preserve normal policy acceptance for unchanged policy.

Root alone designs, codes and improves all bot tooling. Peer Combat only operates tested run commands and supplies gameplay observations. GPU captures serial; bounded engine/media/tests on shared VPS slots. No new packages/frameworks or hooks/timers.
